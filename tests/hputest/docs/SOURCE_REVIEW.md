## 如何复查是否被使用

`make audit`检查每条案例source存在、唯一编号/参数、连续顺序、03～05的N/L范围及排序、未引用案例源码、明确悬空本地引用；输出逐自有文件的静态调用链。动态生成源和条件实验不会被静态结果冒充“已证明可达”。

`make test`验证契约和调度；统一builder对声明的每项生成native包、独立golden/模型、实际RV64 ELF/BIN及机器字，07还检查计时成功路径。原始指令层使用独立整数/C stage oracle，不伪称SEAL或SSA优化等价。

本轮711项默认及6项可选API诊断均完成实际生成/接收和RV64 ELF/BIN构建，相关模型、机器字和07计时边界门禁通过。三位定向编号的SUBTEST日志解析另做针对性修复和复测，低层目标重编后才交付。没有运行RTL/FPGA，不能将构建与模型验证扩写为硬件通过。新增模式的完整非法输入硬件边界、特定RTL watchdog注入、boot等也未因此被宣称覆盖。
